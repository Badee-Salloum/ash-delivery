# Android driver v4 rollout — 2026-09-28

## Reason

The original `com.ashdelivery.driver` v2 APK could not be installed on a Redmi Note 14 / Android 16. A diagnostic APK with package `com.ashdelivery.driver.diagnostic` installed and opened on that handset. Android v4 adopts that package as the production app ID, restores the normal driver app name, and increments `versionCode` from 3 to 4. It uses the same release signing certificate as the diagnostic v3, so v4 can update it without removing its local GPS queue.

## Production switch

- A read-only preflight immediately before the switch found zero open or awaiting shifts. Postflight passed with 79 migrations, zero pending, balanced ledger, and zero tracking-window errors.
- Production `MIN_DRIVER_ANDROID_TRACKER_BUILD` changed from temporary fallback `0` to `4`. The API deployment `dpl_F2JxDBMBa9Xk1XewJnm94K6iQqCk` was promoted to `https://ash-api-xi.vercel.app`. The server now rejects a draft shift start unless recent native readiness reports build 4 or newer and the required GPS, background location, notifications, battery exemption, autostart acknowledgement, and queue checks pass. The gate does not end an already running shift.
- Driver deployment `dpl_BeQr8qKJA6nDTnuQJW5YRnpvqthK` was promoted to `https://ash-driver.vercel.app`. A browser sees the v4 download page and cannot start a shift. Both driver download links point to v4. Admin deployment and migration 0083 were not changed in this switch.
- Stable aliases resolved to those deployment IDs. API `/health`, driver root, and driver `/api/health` returned HTTP 200 after promotion. Production postflight still passed with zero active shifts.

## Device follow-up

The v4 upgrade has not yet been tested on the physical Redmi. Install it over diagnostic v3 without uninstalling v3, then verify the start readiness, foreground tracking notification, GPS diagnostics, and offline queue during a real shift. The previous `com.ashdelivery.driver` app is a separate package; keep it installed until any pending GPS points have uploaded, since uninstalling an app deletes its local queue. The new server gate blocks old packages and browser shift starts without deleting their queued points.
